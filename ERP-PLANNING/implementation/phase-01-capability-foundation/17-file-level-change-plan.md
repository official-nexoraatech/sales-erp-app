1. `capability-registry.ts` + its test (no dependencies).
2. `capability-guard.ts` + its unit test (depends on #1).
3. Integration tests (depend on #1, #2, and a real test DB/Redis).
4. Route-level test with throwaway route (depends on #2).
5. `BillingService.ts` docblock comment (independent, can happen anytime).
6. `navigation.ts` + `Layout.tsx` (frontend filter mechanism, additive and untagged — no dependency on the delivery-mechanism decision).
7. `auth.store.ts` + `LoginPage.tsx` + `client.ts` + `apps/auth-service/src/routes/users.ts` (`/me` route) — all decisions now finalized (`08-frontend-navigation.md` §2, `11-api-contracts.md` §2), no further approval gate before this step.
