## Cross-cutting notes

- **Zero scenarios above require new production logic in Phase 2A.** Every "PHASE 2A BEHAVIOR" cell is either "identical to current" or "unreachable until Phase 2B" — consistent with `28-financial-impact-analysis.md` §5's claim that Phase 2A carries zero financial-behavior change for any tenant on merge, independently re-verified against the actual call sites rather than taken on the plan's word.
- **Pre-existing sales-service test gaps** (not introduced by this migration, not required to be fixed by Phase 2A's acceptance criteria, but worth naming so they aren't mistaken for new regressions): no sales-service-level test exercises multi-layer FIFO partial consumption (#4/#5) or the insufficient-stock error path (#6) end-to-end through `InvoiceService`/`SaleReturnService` — coverage for that logic today lives entirely in `packages/platform-sdk/src/__tests__/valuation-engine-fefo.test.ts` and equivalent engine-level suites for the _other_ three services, not sales-service. This migration does not need to close that gap (the engine logic is already proven there), but it is recorded here per the brief's "test coverage gaps" requirement.
- **Row 10 (Loyalty)** exists specifically to make the correction in `34-phase-2a-preflight.md` §1 traceable from the compatibility matrix itself, not just the preflight doc.
