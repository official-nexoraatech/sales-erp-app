## Manufacturing vs. Job Work Order — a real, documented duplication

`ProductionOrderService.ts` and `JobWorkOrderService.ts` (796 lines, read in full) are **genuinely parallel, independently-implemented systems, not one built on the other.** `ProductionOrderService.ts`'s own header comment (lines 68-73) states this explicitly: it "deliberately mirrors JobWorkOrderService's proven structure... rather than sharing a base class with it — the two are genuinely different documents... and this codebase doesn't abstract order-type services elsewhere." Both independently reimplement stock deduction via `ValuationService`, ledger/projection writes, quality-check entry, status-lifecycle history, and outbox events — including byte-for-byte parallel private methods (`materialsFromBom()` in both files).

This is a documented, deliberate choice, not accidental duplication — `JobWorkOrderService` models outsourced/contract manufacturing (has `supplierId`, GST job-work semantics; this is the Cloth-industry "send fabric to a job worker" pattern), which is a materially different document type from an in-house Production Order. But it is real code-duplication risk: a future stock-posting valuation bug fix (this has already happened once, per `JobWorkOrderService.ts`'s own "Phase 1 consolidation" comments) must be applied in both places, and whether `ProductionOrderService.ts` received the identical historical fix was **not independently re-verified** in this pass. Rated **MEDIUM**.

## CRM/O2C split — confirmed real, not a scaffold

`apps/crm-service/src/main.ts` (211 lines, read in full) registers **22 real route modules** (territory, field-visit, health-scoring, loyalty, festival-intelligence, campaign, journey, quota, CRM dashboard, account, lead, link-tracking, conversation, call, inbound-webhook, opportunity, API-key, public-API, referral, ticket, portal, plus internal routes) with a full production bootstrap (helmet, CORS, rate limiting, correlation IDs, Prometheus metrics, health route, tenant-status checks) mirroring `sales-service/src/main.ts` byte-for-byte per its own comment. Spot-checked domain files (`QuotaService.ts`, `FestivalIntelligenceService.ts`) exist with accompanying substantive test files. **This independently confirms — via direct code inspection, not by trusting a prior session's memory — that the split is a real, fully-wired service today,** superseding any stale "scaffold only" characterization.
