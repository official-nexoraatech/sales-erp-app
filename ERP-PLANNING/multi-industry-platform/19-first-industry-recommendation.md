## 2. Recommendation: Distribution or Manufacturing, not Hotel

**Primary recommendation: Distribution**, if the goal is to validate the Business Profile/Module/Capability pipeline (Phases 1–5) with the lowest engineering risk, fastest time-to-first-industry, and clearest reuse-vs-fork signal — it stress-tests configuration (new `business_types` row, mostly-reused module set) more than it stress-tests new domain modeling, which is appropriate for a _first_ validation run of new platform infrastructure.

**Secondary/parallel recommendation: Manufacturing**, if the goal is instead to retire a known gap (`production-service`'s existing QA-flagged issues) while simultaneously proving the module system handles a service that needs _several_ new modules (BOM, Work Centers, MRP) rather than mostly-existing ones — a better test of the Module Registry's ability to compose multiple new capabilities under one business type, at higher engineering cost than Distribution.

**Do not pick Hotel or Healthcare first.** Both require the most net-new domain modeling of any candidate, the least code reuse, and (Healthcare) the highest regulatory complexity — exactly the profile that makes them the _worst_ choice for validating brand-new platform infrastructure, since a failure to onboard cleanly would be ambiguous (is the Business Profile model wrong, or is Hotel just a hard domain?). Validate the pipeline on a low-risk candidate first; Hotel/Healthcare become reasonable choices for a _later_ phase once the module system has proven itself on 1-2 easier verticals (matches Phase 12's "review checkpoint" framing).

**Restaurant/Bakery** are good **third-vertical** candidates specifically because they exercise Phase 7's Commerce Core generalization (batch/expiry, UOM) under a different pattern (ingredient consumption vs. Grocery's resale-as-is), which is valuable precisely _because_ Phase 7 will already exist by then — not a reason to pick them first.

## 2b. Correction (verified 2026-08-18)

The table above cites Grocery's batch/expiry and UOM-conversion gaps as reasons Restaurant/Bakery need Phase 7 to land first. **That work has since shipped** (migrations `0165`–`0168`, real consuming code in `GRNService.ts`/`PromotionService.ts`/`DayEndSettlementService.ts`/`nearExpiryAlert.job.ts` — see `02-gap-analysis.md` G8's correction note). This makes Bakery marginally more viable sooner than this document originally suggested, though the core ranking (Distribution/Manufacturing first, Hotel/Healthcare last) is unaffected — it was never based on the batch/expiry gap in the first place.
